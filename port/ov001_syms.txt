# HUD::RenderCoinCount and its siblings draw through tables the decomp names
# func_020ab948 / func_020ab9c8 / func_020aba70 / func_020abad0 / func_020abad8
# -- addresses dsd could not attribute, because ov000 and ov001 share the base
# 0x020aa420 and the decompiler picked the wrong one. ov000 holds FILENAME
# STRINGS at those addresses ("data/player/...", "snd_drop_leg.bca"); ov001
# holds OamAttr records. config names every one of them in ov001:
#
#     func_020ab948  OAM::LIFE_ICONS     func_020abad0  OAM::POWER_STAR
#     func_020ab9c8  OAM::TIMES          func_020abad8  OAM::COIN
#     func_020aba70  OAM::NUMBERS
#
# OAM::NUMBERS and OAM::LIFE_ICONS are POINTER TABLES into this same block --
# NUMBERS is ten pointers at 0x020aba68 down to 0x020aba20, one per digit -- so
# the whole run is mounted together and ovdata's own pointer pass rewrites them
# to host addresses. That is why this is the entire 0x020ab800..0x020abb00
# span and not the five symbols the linker asked for.
#
# hal/sub_actors.cpp carries the func_* -> OAM:: aliases; both names are data
# at the same address, so each alias is exact.
