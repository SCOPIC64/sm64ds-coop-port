# Gate 40: the castle interior's STAR_DOOR (actor 354, ov100), x1.
#
# The last id the castle interior's object tables leave the census printing as
# skipped. It is a class in its own right, NOT the DOOR gate 22 already hosts,
# and the config's naming is what hides that: gate 22 found that the vtable at
# ov100 0x02148188 (RTTI 8daDoor_c) is the real door and config left it unnamed
# as data_ov100_02148188, while config's `_ZTV4Door` is a DIFFERENT table
# (RTTI 12daStarGate_c) and the whole _ZN4Door* method family hangs off THAT
# one. So the star door wears the "Door" name and the real door's methods are
# the unnamed func_ov100_* block. gate 22 hosts the real door; this hosts the
# star door, compiling the files config's _ZN4Door* names really point at and
# renaming nothing -- the gate-17 reading for the same overlay a second time.
#
# StarDoor_SpawnInfo (ov100 0x021483a8) is already mounted by the per-symbol
# ov100 mount (ov100_syms.txt); its +4 halfword reads 354. The registry
# rewrites its +0 factory word to StarDoor_Spawn. StarDoor_Spawn installs
# _ZTV4Door, which hal/actor_classes.cpp fills as hal_fill_star_door_vtable
# (aliased to _ZTV12daStarGate_c, the name the class's own D0 spells -- the
# RABBIT's dual-name treatment).
#
# NO CALLBACK SEAT IS NEEDED. InitResources calls func_ov100_02145f68, which
# stores data_ov100_02148974 at the actor's +0x110 and dispatches word 0 of it
# only if non-zero; 0x02148974 is in ov100's .bss (past the image end
# 0x02148600), so it loads zeroed and the dispatch is guarded off. Behavior
# reads the same +0x110 node and guards its own dispatch on the callback being
# non-zero, so both PMF sites are dead on a fresh boot. Both PMFs are formed
# over COMPLETE local classes (struct Base {} / struct C), so MSVC's smallest
# representation applies and no host copy is required.

# ---- the own slots --------------------------------------------------------

# references to base destructors no TU defines. Slot 16 reuses ac_d1_door
# instead -- the member chain is identical (a CommonModel at 0xd4) -- so the
# ROM-faithful teardown runs without that shadow. D0 (slot 17) is plain C and
# is here.
