# ov065 is an ACTOR overlay (base 0x02115ee0, its own window, shared by
# address with ov063/ov075 -- see the alias check below), one of the overlays
# level 13 (Hazy Maze Cave) loads. It carries FOURTEEN classes: the HMC four
# -- Snufit (236), Swoop (237), Dorrie (168), DorrieCap (169) -- and the ten
# Ttc* classes (108-118), whose level (TTC) has no bootable row today. The
# Ttc* subset is PARKED per the wave-5 census: its data rides this mount
# (whole-data-span doctrine) but no Ttc registry row exists, no Ttc sinit
# runs, and no Ttc TU is sliced. Wiring code with zero reach is the measured
# gate-6 mistake at pack scale (census part 2).
#
# This is a first mount (ov065 was never in PORT_ACTOR_OVERLAYS); the
# ov079/ov080/ov095 shape: SpawnInfo records, state-record source statics,
# file-pointer tables and the sinit-built SharedFilePtr bss, all BY NAME.
#
# ==== MANDATORY WINDOW-ALIAS CHECK (the gate-199/202 rule) ==================
# All four HMC SpawnInfo addresses are flagged `ambiguous` in config/arm9/
# overlays/ov065/symbols.txt (ov063/ov065/ov075 share this window). RESOLVED
# by reading the raw bytes out of extracted/overlays/overlay_0065.bin (base
# 0x02115ee0 -- the dsd export extracted/dsd/arm9_overlays/ov065.bin is a
# DELINKED image whose relocated words are rebased by the export, so reading
# record words out of it reads rewritten values, not the ROM's), against the
# arm9 spawn table at
# 0x02090864 + id*4 in extracted/arm9_dec.bin:
#   id 236 -> 0x0211cb80  word[0]=0x02116f48 Snufit_Spawn     word[1]&0xffff=236
#   id 237 -> 0x0211cc7c  word[0]=0x02117ee8 Swoop_Spawn      word[1]&0xffff=237
#   id 168 -> 0x0211cd84  word[0]=0x02119634 Dorrie_Spawn     word[1]&0xffff=168
#   id 169 -> 0x0211cda0  word[0]=0x021195ec DorrieCap_Spawn  word[1]&0xffff=169
# Every record's spawn word lands inside ov065 itself and every id matches the
# spawn-table slot it was reached from. UNLIKE ov045, the dsd names here are
# NOT shifted: each class's D1..Init..Spawn run is contiguous and its _ZTV
# lands right after its own SpawnInfo -- verified per class by (4) each
# table's slot 0 landing in that class's own code block and (5) each Spawn's
# own vtable-store relocation naming that table.
#
# ==== CORRECTION, run linkw wave 17 (lane w17) =============================
# THAT PARAGRAPH IS TRUE OF THE HMC FOUR AND FALSE OF THE Ttc SUBSET, and it
# was only ever verified against the HMC four. The Ttc *_SpawnInfo and
# *_Spawn names are fine -- every record still reads its own id back at +4
# and every word[0] lands inside ov065 -- but the dsd _ZTV names ARE shifted
# from 0x0211d3b4 on, each carrying the PREVIOUS class's name. Identity taken
# from the RTTI record at vtable[-1], out of the shipped image:
#
#   table       dsd Ttc spelling            RTTI at vtable[-1]      verdict
#   0x0211d028  _ZTV15TtcRotatingCube       20daObjCtRotateBlock_c  ok
#   0x0211d1ec  _ZTV20TtcConveyorBeltLarge  16daObjCtMecha04_c      ok
#   0x0211d3b4  _ZTV13TTC_MovingBar         18daObjCtKaitendai_c    SHIFTED
#   0x0211d494  _ZTV15TtcRotatingGear       16daObjCtMecha08_c      SHIFTED
#   0x0211d568  _ZTV14TtcMovingCubeA        16daObjCtMecha09_c      SHIFTED
#
# TTC_MovingBar is id 113 (record 0x0211d290), TtcRotatingGear is id 114
# (0x0211d374) and TtcMovingCubeA is id 116 (0x0211d454) -- each one class
# earlier than the table dsd hangs its name on. The dsd RTTI spellings are
# right on all five. The practical trap: TtcRotatingGear_Spawn is id 114's
# FACTORY while _ZN15TtcRotatingGear* are ids 116/117's BODIES, so the same
# prefix names two different classes in this overlay. Anyone hosting these
# tables should name the arrays for the RTTI and alias the Ttc spellings on.
#
# ALSO CORRECTED: the five Ttc tables are 32-slot PLATFORM tables. Slot 31 of
# every one of them is 0x020ee55c = _ZN8Platform4KillEv (ov002, already in
# the build), slot 30 is Actor::OnAimedAtWithEggReturnVec, and the typeinfo
# terminator 0x0209a764 opens at slot 32. Every Ttc Spawn constructs with
# _ZN8PlatformC2Ev, which says the same thing from the other side. A wave-16
# note recording "32 slots ... no Platform::Kill tail, plain Actor shape" is
# wrong on its second half.
#
# AND THE BLOCKER THAT ACTUALLY HOLDS THIS SUBSET, which is neither the
# registry nor the sinits nor the vtables: EVERY Ttc CLASS READS DATA OUT OF
# THE LEVEL OVERLAY. The three-column tables their InitResources index put a
# level-window address in their third column, and the relocs say so:
#
#   from 0x0211cfd8 -> 0x02112138   CLPS, 108/109   module:overlays(12,13,
#   from 0x0211cfe4 -> 0x02112178   CLPS, 108/109     24,33,35,43,45,47,
#   from 0x0211d16c -> 0x0211208c   BTA anim, 111/112 52,53,56)
#   from 0x0211d364 -> 0x021120f8   CLPS, 114/115
#   from 0x0211bb68 -> 0x021121b8   CLPS, 116/117 (spelled func_021121b8)
#
# Those are CLPS blocks and a texture-animation BTA belonging to whichever
# LEVEL overlay is loaded -- ov035 on level 27. The port mounts level
# overlays --whole, and tools/ovdata.py's cross pass deliberately refuses to
# rebase into a whole-image mount ("a whole-image mount PROVIDES NOTHING to
# the cross pass ... which is what keeps the level overlays honest"). So the
# words stay DS addresses, and a seated class hands
# MovingMeshCollider::SetFile a DS pointer as its CLPS_Block.
#
# MEASURED, with the cluster seated and level 27 mounted: ids 108 (x8) and
# 114 (x5) spawn and tick 300 frames without faulting -- SILENTLY, on a
# garbage CLPS -- and id 112 faults c0000094, an integer divide by zero in
# Animation::Advance +0x1e reached from TtcConveyorBeltLarge::Behavior
# +0x10e, because its BTA read zero frames. The quiet two are the worse half
# of that result, and they are why the seat was taken back out.
#
# So the subset is NOT "records done, only the fill side missing". It is
# blocked on a PER-SYMBOL MOUNT OF THE LEVEL OVERLAY (ov035 for TTC) for the
# four CLPS blocks and the two BTA files above, plus a cross-pass rebase onto
# them. Everything else it needs is now measured: 43 TUs, zero guess markers,
# zero cross-overlay spellings, four 32-slot Platform tables with their RTTI
# names, four sinits with their owners (below), and the record widths pinned.
#
# TWO SHARED-WINDOW NAME RACES, resolved against ov065's OWN config (the
# probe's p10 list carried them under the ov075 spelling): the Snufit state
# TUs spell two of their SharedFilePtrs data_ov075_0211d608 / _0211d650.
# Both addresses are ov065 bss (config lines 267/274, built by Snufit's own
# sinit 0x0211c110); the ov075 names are another module's dsd export winning
# the naming race at a shared-window address. Aliased onto the ov065 mount
# names in hal/actor_classes_ov065.cpp; nothing named ov075 is mounted here.
# The probe's two _ZTV16daObjCtMecha03_c/_05_c externs are NOT ov065 names at
# all (not in its config) -- they are Ttc-subset dtor spellings from the same
# race, and the Ttc TUs that spell them are parked with their subset.
#
# ==== NINE VTABLE SPANS LEFT OUT ===========================================
# The four HMC tables are HOST ARRAYS hal/actor_classes_ov065.cpp fills (the
# ov015/ov016/ov080 rule -- a mounted vtable hands a factory DS code

# ==== STATE-RECORD SOURCE STATICS: DS CODE ADDRESSES =======================
