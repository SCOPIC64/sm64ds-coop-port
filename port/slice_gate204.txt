# Gate 204 (run linkw wave C, lane cat-ov002): the ov002 DELETING DESTRUCTORS
# the port hand-spelled or declined -- slot 17 on three seated ov002 classes.
#
# WHAT SLOT 17 IS AND WHY IT WAS EMPTY. Slot 16 is the complete-object
# destructor (D1) and slot 17 the deleting one (D0): the same member chain plus
# a Memory::Deallocate of the object. The ROM's destroy path runs D1 through
# slot 16 and lets ActorBase::AfterCleanupResources do the deallocation, so
# nothing in the game dispatches slot 17 -- which is exactly why every ov002
# seat in this port left it on a trap (bw_trap17) or hand-spelled it. Neither
# is the ROM's word. The ROM's word is the class's own D0 body, and each of the
# three below is a matched TU sitting in src/ with nothing referencing it.
#
# THIS IS THE w2_dtor_heads ARGUMENT, applied per class instead of per table:
# Release links with /OPT:REF, so a matched TU on a slice line with no
# reference is dropped before the map is written. A ROM vtable slot the port
# never filled is the honest place to put the reference, because the ROM says
# what belongs there.
#
# BEHAVIOUR. Coin, HealingHeart and Cap all sat on bw_trap17, which declines by
# name; PushBlock had a host thunk spelling the chain by hand. Nothing
# dispatches slot 17 on any of them, so what changes is that the port's copy of
# each table now carries the word the ROM puts there, and the hand-spelled copy
# of PushBlock's chain is replaced by the body it was transcribed from.
#
# EACH BODY, AND WHY IT COMPILES AS-IS (all three are flat C, none carries the
# inferred-stub marker, and every callee is already in walk_window.map):
#
