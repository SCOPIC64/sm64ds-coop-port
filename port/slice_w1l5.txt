# slice_w1l5.txt -- lane-owned slice for the linkage campaign (run linkw).
# One matched src TU per line, path relative to the repo root, comments with #.
# THIS FILE HAS ONE OWNER (lane l5); other lanes never touch it, which is what
# keeps five parallel seat lanes out of CMakeLists.txt and each other.
#
# Lane l5 is the PLAYER family: Player methods, the St_ state bodies, the
# state dispatcher's targets, and the ov002 helpers the player module calls.
#
# READ THIS BEFORE ADDING A LINE. A slice line COMPILES a TU; it does not put
# it in the binary. walk_window links Release with /INCREMENTAL:NO, so /OPT:REF
# strips every object nothing references, and port/tools/linkage.py counts a TU
# as linked only when its .obj survives into walk_window.map. So a seat only
# moves the number when something already in the binary REACHES it. For this
# family that reach is hal_call_state_fn in port/hal/player_bridges.cpp: the
# ROM's state records hold DS code addresses, the dispatcher switches on them,
# and a case there is what makes a St_ body live. Everything below is split
# along exactly that line, because a seat with no reach reads like progress and
# is not.

# (b) The name is a community symbol for ANOTHER overlay's bytes at a shared
#     address, so seating it would put a second body of a function the port

#     header essay in hal/method_faces.cpp, bought for nothing:
#       _ZN6Player18St_LevelEnter_MainEv   0x020c6f3c is dispatched to
#         port/unmatched/func_ov002_020c6f3c.cpp, which exists because MSVC's

#         records by four. The raw src body has that bug.
#       _ZN6Player23St_InYoshiMouth_CleanupEv  ov006's 0x020d6084; the .inc
#         dispatches that address to func_ov002_020d6084.
#       _ZN6Player12St_Null_InitEv         ov006's 0x020cac30; same shape.
#       _ZN6Player6ST_OWLE                 an ov006 class, not a Player member
