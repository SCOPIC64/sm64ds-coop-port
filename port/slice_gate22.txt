# Gate 22: ov100's DOOR, the last class the castle grounds names.
#
# Actor 353 x3 -- the castle's own doors, loaded by LoadDoorObjects (the
# level's kind 0x09, count 3) rather than by the standard or simple loader,
# which is why they carry no position in the object tables the other classes
# come out of. The overlay is already mounted (gate 21, port/ov100_syms.txt).
#
# THE CLASS IS UNNAMED IN CONFIG AND ITS NAME IS TAKEN. Door_Spawn installs
# the vtable at ov100 0x02148188, which config calls data_ov100_02148188 and
# the ROM's RTTI calls 8daDoor_c; config's `_ZTV4Door` is a DIFFERENT table at
# 0x021483cc whose RTTI reads 12daStarGate_c, and the whole _ZN4Door* method
# family hangs off that one. So the star door wears the door's name and the
# door's own methods are the unnamed func_ov100_02144xxx / 021454xx block.
# The port compiles the files the vtable points at and renames nothing -- the
# gate-17 reading, for the third overlay running.
#
# That is also why port/ov100_syms.txt has to exclude 0x02148188 by address:
# the "_ZTV*" rule cannot see a vtable dsd left as data_ov100_*, and mounting
# it would hand Door_Spawn a table of DS code addresses instead of the host
# array hal/actor_classes.cpp fills.
