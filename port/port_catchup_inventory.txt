# THE JOIN IS BY ADDRESS AND ONLY BY ADDRESS. Names drift between the two
# branches in both directions -- main renamed twelve ov015/ov064/ov080/ov100
# bodies onto the class next door, and this branch still spells them the old
# way -- so a join on file names or symbol names invents rows and misses rows.
# Every row below is keyed on a ROM address and carries the evidence for both
# sides of the join.
#
# HOW THE CANDIDATE SET WAS DERIVED, so it can be re-derived rather than
# trusted:
#
#   1. config delink blocks were parsed out of all 106 modules on BOTH refs
#      (arm9, itcm, dtcm, 103 overlays), giving {module, section, [start,end)}
#      -> src path per ref.
#   2. config symbols.txt was parsed the same way on both refs, giving
#      {symbol -> address} per module per ref.
#   3. walk_window.map (this tree's own build at 8aabc9415) was parsed for
#      every symbol and its defining object, and objects whose stem is not
#      itself a src/ TU were taken as HOST objects.
#   4. a host-defined symbol was resolved to an address through either ref's
#      symbols.txt, then that address was looked up in both refs' delink
#      spans.
#
# The raw counts, all measured in this worktree:
#
#     571   host-defined ROM symbols in the map that carry a config address
#     308   of those whose address has a matched TU on origin/main that is
#           not linked here (mostly documented host-ABI exceptions, not drift)
